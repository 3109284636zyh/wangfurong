# AI小福小程序底部导航与页面重构规划

> 本文档仅做产品与实现规划，不包含开发改动。目标是在不推翻现有项目、不破坏客服/AI聊天模式边界的前提下，把小程序首页结构梳理得更清晰、更像正式产品。

## 1. 背景

当前小程序主要围绕一个首页承载多种能力：

- 建站接单客服助手：输入客户咨询，一键生成合规回复。
- AI小福聊天：陪伴聊天、聊天形态选择、独立聊天页入口。
- 产品/报价能力：由后台产品库支撑客服回复，但小程序侧的产品展示和入口还不够清晰。
- 设置、说明、辅助功能与主流程混在一起，页面观感偏重、层级不够明确。

本次规划希望把小程序改成更清楚的三栏底部导航：

```text
首页  |  电商  |  我的
```

其中：

- 首页：作为总入口，突出“产品功能详情”和“AI聊天对话”。
- 电商：承接产品、套餐、建站服务、报价说明等交易前信息展示，不做支付/会员/充值。
- 我的：承接设置、说明、关于、清缓存、聊天偏好等非主流程功能。

## 2. 规划目标

1. **视觉更清爽**：首页减少长表单和大量说明堆叠，改成入口式卡片布局。
2. **功能更好找**：把“建站产品/服务”和“AI聊天”从一个混合页面中拆出明确入口。
3. **底部导航明确**：形成“首页 - 电商 - 我的”的基础信息架构。
4. **保留项目方向**：继续围绕“建站接单客服助手 + AI小福陪伴聊天”。
5. **不新增账号/支付体系**：电商页只做产品/套餐展示和咨询辅助，不做用户登录、下单、支付、会员、充值。
6. **不破坏风控边界**：客服模式仍走合规回复和违禁词检测；AI聊天模式仍保持独立体验。

## 3. 页面信息架构

### 3.1 底部 Tab

| Tab | 建议名称 | 定位 | 主要内容 |
| --- | --- | --- | --- |
| 首页 | 首页 | 总入口和核心能力聚合 | AI小福欢迎区、产品功能详情入口、AI聊天入口、客服助手快捷入口 |
| 电商 | 电商 | 建站服务/产品/套餐展示 | 产品分类、产品详情、报价说明、适合场景、咨询话术入口 |
| 我的 | 我的 | 设置与辅助功能 | 设置、聊天偏好、清理缓存、使用说明、关于项目 |

### 3.2 建议页面列表

> 页面命名仅为规划建议，实际开发时可结合现有文件增量调整。

```text
miniprogram/pages/index/index              首页 Tab
miniprogram/pages/ecommerce/ecommerce      电商 Tab
miniprogram/pages/profile/profile          我的 Tab
miniprogram/pages/product-detail/detail    产品/功能详情页
miniprogram/pages/chat/chat                AI聊天对话页（沿用现有独立聊天页）
miniprogram/pages/settings/settings        设置页（从“我的”进入）
```

如希望开发量更小，可以先只新增三个 Tab 页面，把详情页和设置页作为二期。

## 4. 首页规划

### 4.1 首页定位

首页不再承担所有输入和说明，而是作为“进入核心功能”的门户。

首页建议展示：

1. 顶部品牌区
   - 标题：AI小福
   - 副标题：建站接单客服助手 / 你的 AI 聊天伙伴
   - 风格：干净、轻量、卡片化，避免大面积复杂渐变和密集文字。

2. 核心入口卡片
   - 产品功能详情
     - 文案示例：查看建站服务、套餐和能力说明。
     - 跳转：产品详情或电商页的推荐产品区域。
   - AI聊天对话
     - 文案示例：进入 AI小福，开始陪伴聊天。
     - 跳转：现有 `pages/chat/chat` 或新的聊天入口页。

3. 客服助手快捷入口
   - 文案示例：粘贴客户咨询，生成合规回复。
   - 用于保留建站接单客服助手主方向。
   - 可在首页放一个轻量按钮，点击后进入客服回复区域/独立客服助手页。

4. 今日推荐/常用能力
   - 推荐建站套餐。
   - 常见客户问题。
   - 快捷生成回复。

## 5. 电商页规划

### 5.1 电商页定位

电商页用于展示建站服务、产品套餐、报价说明和适合场景，帮助用户快速理解可售卖内容。

注意：这里的“电商”不等于完整交易系统，当前阶段不规划支付、下单、用户账户、会员、充值等功能。

### 5.2 主要模块

1. 产品分类
   - 企业官网
   - 落地页/活动页
   - 小程序
   - 后台管理系统
   - 维护/改版/部署服务

2. 产品列表
   - 产品名称
   - 简短卖点
   - 参考价格/价格区间（如后台已有产品价格则读取）
   - 适合客户
   - 查看详情按钮

3. 产品详情
   - 服务内容
   - 交付范围
   - 周期说明
   - 常见问题
   - 可复制咨询回复/报价话术

4. 与客服助手联动
   - 在产品详情页提供“生成客户回复”入口。
   - 把产品信息作为用户选择上下文，辅助客服模式生成更贴合产品的回复。
   - 仍然保持客服模式风控和违禁词检测。

### 5.3 电商页交互草图

```text
└─────────────────────────┘
```

## 6. 我的页与设置归类

### 6.1 我的页定位

“我的”页只放非核心工作流内容，降低首页复杂度。

建议模块：

1. 用户/产品信息卡片
   - AI小福标识
   - 当前定位：建站接单客服助手
   - 简短说明

2. 常用入口
   - 设置
   - 使用说明
   - 清理聊天缓存
   - 关于 AI小福

3. 状态信息
   - 当前 API 环境提示（如需要）
   - 当前聊天形态偏好
   - 真人模式是否开启（仅展示，不做账号体系）

### 6.2 设置页建议归类

设置页承接“其他功能”，避免堆在首页：

- 聊天设置
  - 默认聊天形态：日常/朋友/闺蜜/兄弟/恋人。
  - 是否保留本地聊天记录。
- 客服助手设置
  - 默认进入客服模式或 AI聊天入口的偏好。
  - 常用平台提示：闲鱼/淘宝/拼多多。
- 缓存与数据
  - 清空本地聊天历史。
  - 清空上次模式选择。
- 关于与说明
  - 使用说明。
  - 风控说明。
  - 版本信息。

后台管理类配置仍然留在管理后台，不建议放到小程序“我的”中。

## 7. 核心流程规划

### 7.1 查看产品功能详情

```text
首页 → 产品功能详情 → 产品/套餐详情 → 复制卖点或生成客户回复
```

目标：让用户先理解产品，再服务客户咨询。

### 7.2 进入 AI 聊天对话

```text
首页 → AI聊天对话 → AI小福聊天页
```

目标：把陪伴聊天作为清晰入口，不和客服回复表单挤在同一屏。

### 7.3 使用客服助手

```text
首页 → 客服助手快捷入口 → 输入客户咨询 → 生成合规回复 → 复制发送
```

目标：保留当前项目最核心的建站接单客服工作流。

### 7.4 修改设置

```text
我的 → 设置 → 调整聊天偏好/清理缓存/查看说明
```

目标：把低频功能从首页移走。

## 8. 实施阶段建议

### 第一阶段：只做导航与首页重排

目标：小步改动，先解决“结构丑、入口乱”的问题。

- 增加底部 Tab：`首页 / 电商 / 我的`。
- 首页改成入口式卡片布局。
- AI聊天入口跳转到现有聊天页。
- 设置等低频功能先移动到“我的”页入口。
- 不改后端接口，不改数据库。

### 第二阶段：完善电商页

目标：让产品库能力在小程序侧可见。

- 从现有公开产品接口读取启用产品。
- 增加产品分类、产品列表、产品详情。
- 在详情页增加“生成客户回复”入口。
- 保持产品数据来源于后台产品库。

### 第三阶段：完善设置页

目标：把偏好和缓存管理收敛到“我的 > 设置”。

- 默认聊天形态设置。
- 清空聊天记录。
- 清空上次选择模式。
- 使用说明和版本信息。

### 第四阶段：视觉统一与体验打磨

目标：让整体更像一个产品，而不是功能堆叠。

- 统一卡片圆角、阴影、间距、按钮样式。
- 统一首页、电商、我的的标题风格。
- 优化空状态、加载状态、错误提示。
- 控制文案密度，减少长段说明。

## 9. 预计影响范围

仅规划层面，后续开发可能涉及：

| 范围 | 可能文件 | 说明 |
| --- | --- | --- |
| 小程序配置 | `miniprogram/app.json` | 增加 tabBar 和新页面路径 |
| 首页 | `miniprogram/pages/index/index.*` | 从大表单改为入口聚合页 |
| 电商页 | `miniprogram/pages/ecommerce/ecommerce.*` | 新增产品展示 Tab |
| 我的页 | `miniprogram/pages/profile/profile.*` | 新增设置与说明入口 |
| 设置页 | `miniprogram/pages/settings/settings.*` | 可二期新增 |
| 聊天页 | `miniprogram/pages/chat/chat.*` | 尽量沿用现有独立聊天页 |
| 后端 | 暂不需要 | 优先复用现有公开产品和聊天接口 |
| 数据库 | 暂不需要 | 不新增表，不改字段 |

## 10. 设计原则

1. **入口清晰优先**：首页只放最重要的 2-3 个入口。
2. **卡片化布局**：减少复杂背景、密集按钮和大段说明。
3. **客服与聊天分离**：客服回复、AI陪伴聊天、产品展示各有明确位置。
4. **电商不做交易闭环**：当前只展示产品和辅助回复，不做支付与账号体系。
5. **设置低频后置**：设置、说明、清缓存等统一放到“我的”。
6. **增量改造**：尽量复用现有 `index` 和 `chat` 能力，避免整体重写。

## 11. 验收标准

后续开发完成后，可按以下标准验收：

- 底部导航显示为：首页 / 电商 / 我的。
- 首页首屏能清楚看到“产品功能详情”和“AI聊天对话”两个入口。
- 首页仍能进入客服助手生成合规回复。
- 电商页能查看建站产品/服务/套餐信息。
- 我的页能找到设置入口，设置和其他低频功能不再堆在首页。
- AI聊天入口能进入独立聊天体验。
- 客服模式仍保留违禁词和平台合规风控。
- 没有新增登录、注册、支付、会员、充值功能。

## 12. 待确认问题

开发前建议确认以下细节：

1. “电商”Tab 名称是否固定叫“电商”，还是更偏业务地叫“产品”或“服务”。
2. “产品功能详情”是进入单独详情页，还是进入电商 Tab 的推荐产品区域。
3. 客服助手是保留在首页内展开，还是做成单独页面入口。
4. 设置页第一版需要包含哪些项：聊天形态、清缓存、使用说明、关于，还是只做基础入口。
5. 首页视觉风格偏“科技蓝紫”还是偏“简洁白底卡片”。
